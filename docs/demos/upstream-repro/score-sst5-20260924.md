# Can Jev's Score primitive rate fine-grained sentiment? SST-5, Jev vs Haiku (bead `jev-zui`)

ScoreSST5 (background agent of pane 1, AmberWillow), 2026-09-24. Live lane, model pinned `jev-1.13.0`.

## Preregistered (committed before the first call)

**Question.** Score is one of Jev's three primitives and had never been measured in this lane against
an incumbent (AGENTS.md RULE 14). Ordered labels are what Score claims to handle. On a public,
externally labelled ordinal set, does one Score question beat the two constant predictors and match
or beat Claude Haiku 4.5 asked the identical question through TypeSafe's own adapter?

**Corpus.** SST-5 (Stanford Sentiment Treebank, fine-grained), test split, as published in the Hugging
Face dataset `SetFit/sst5`, file `test.jsonl` at revision `e51bdcd8cd3a30da231967c1a249ba59361279a3`
(<https://huggingface.co/datasets/SetFit/sst5/resolve/e51bdcd8cd3a30da231967c1a249ba59361279a3/test.jsonl>),
2,210 rows, sha256 `1384216112a34f3d70b6fa210762f3399bb080410c0456ac6e54a5cb413f04b2`. Labels 0 very
negative, 1 negative, 2 neutral, 3 positive, 4 very positive; the labels are the treebank's, not ours.
Sample: `work/score-sst5/sample.jsonl`, 500 rows drawn without replacement by
`random.Random(20260924)`; rebuild with `python3 work/score-sst5/sample.py 500 20260924`
(fetches the pinned revision, refuses a sha256 mismatch, byte-identical on rerun: sample sha256
`522bee6e46027527bf74232cb281a8babd52305ca1aef51940442cb2b567d903`). Label counts in the sample:
75 / 145 / 93 / 104 / 83.

**The question, frozen** (`work/score-sst5/run.py`, `QUESTION`). State = the sentence text, as a string.
One Score question, instructions *"How positive is this movie review sentence?"*, criteria in order:

0. Very negative: strongly critical, scathing, or contemptuous
1. Negative: somewhat critical or unfavorable
2. Neutral: neither positive nor negative, or evenly mixed
3. Positive: somewhat favorable or approving
4. Very positive: strongly enthusiastic, glowing, or full of praise

**Arms.**
- **Jev:** official `typesafe_sdk` 0.7.0 (`upstream/typesafe-ai/typesafe-sdk-python` @ `0ffd094`),
  `AsyncTypeSafeClient(model="jev-1.13.0", retry=RetryPolicy())`.
- **Incumbent:** the same `Score` object, same state, through `system-one-adapter-python` 0.2.0
  (@ `adffc2e`), `anthropic/claude-haiku-4-5`, structured outputs, `llm_answer_mode="probabilities"`,
  probabilities normalized. The adapter computes the expected score from the returned distribution.
- **Constants** (computed before any call by `python3 work/score-sst5/score.py` and
  `node work/jev-prevalence-first/prevalence-check.mjs work/score-sst5/sample.jsonl --truth label`):

| Constant | Exact correct | Accuracy | MAE (levels) |
|---|---:|---:|---:|
| majority class (always 1, negative) | 145/500 | 29.0% | 1.250 |
| middle level (always 2, neutral) | 93/500 | 18.6% | 1.130 |

**Predicted level.** Primary: the returned expected score rounded, `floor(score + 0.5)` clamped to
0..4. Also recorded and reported (not used in the pass rule): the argmax level of `probabilities`,
ties to the lower index.

**Metrics.** Exact accuracy (predicted level == label) with a Wilson 95% interval, and mean absolute
error in levels, over all 500 rows. A row that still has no answer after the runner's resume pass is
scored as incorrect with the worst possible error for that row, `max(y, 4 - y)`.

**Paired tests** (same 500 rows, alpha 0.05, two-sided):
- accuracy: McNemar exact (binomial on the discordant exact-correct pairs);
- MAE: exact sign test on the per-row absolute errors (rows with equal error dropped).

**Pass rule.**
1. Jev beats both constants: against each, accuracy WIN (McNemar p < 0.05, Jev higher) **and** MAE
   WIN (sign test p < 0.05, Jev lower).
2. Jev does not lose to Haiku: neither the accuracy test nor the MAE test is a significant Haiku win.
   A non-significant difference is reported as TIE, not as parity proven.
3. **PASS** = 1 and 2. If Jev fails 1, or loses to Haiku on either metric, a `NEGATIVE_EVIDENCE.md`
   row is written with a retry condition. No criteria, instructions or rounding rule is retuned after
   seeing an answer.

**Stated before running:** 500 Jev requests and 500 Haiku requests (one question each), concurrency
8, per-call wall-clock latency p50/p95 and reported token usage per arm. Descriptive only, not part of
the pass rule: argmax accuracy/MAE, MAE of the raw expected score, a coverage-by-returned-confidence
table (top 25/50/75/100% of rows), a calibration table by confidence bin, and a confusion matrix.

**NO-CLAIM.** One public set (movie-review sentences), one question wording, one Jev model version,
one Haiku version. Nothing here says Score works on other ordinal tasks or other rubrics, and a TIE is
not evidence of equivalence.
