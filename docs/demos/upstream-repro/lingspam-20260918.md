## What was run

```bash
cd jev-spam-eval
sh fetch_lingspam.sh                                   # sha256 pinned by the script, verified OK
uv run python tfidf_baseline.py --dataset lingspam
```

The corpus is Ling-Spam (Androutsopoulos et al., ECML 2000), fetched from `aueb.gr` and checked
against the `SHA256` the upstream script pins. No API key. Jev's answers are already in the repo, so
this reproduces the comparison without spending a call.

## Reproduction against the published README

| | upstream README | measured here |
|---|---|---|
| TypeSafe, bare question, **0 labels** | 98.6% | **0.9857** acc · 0.9898 balanced · AUC 0.9996 |
| TF-IDF naive Bayes, all ~2.3K labels | 99.4% | **0.9941** acc · 0.9844 balanced · AUC 0.9997 |

**Both headline figures reproduce.** The README's framing also holds at the error level rather than
only in the summary: the zero-label question makes **2 false negatives and 39 false positives**,
while TF-IDF logreg trained on 2,300 labels makes **40 false negatives and 1 false positive**. Same
accuracy to four decimals, opposite failure shapes — the labelled classifier protects precision, the
question protects recall.

## What is worth building on, and why it is not another demo of ours

1. **`structured criteria` scored WORSE than the bare question here** — 0.9701 against 0.9857. The
   README warns about this in the other direction, noting its 98.3% came from a question written
   after reading 1,000 sampled mistakes. On Ling-Spam the elaborated question *lost* 1.6 points.
   That is a real, reproducible finding about prompt elaboration, measured on someone else's data
   with someone else's baseline.
2. **The ensemble beats both** — averaging structured criteria with logreg gives 0.9983 accuracy, 4
   false negatives and 1 false positive, better than either alone. A zero-label question and a
   labelled classifier are not competitors.
3. **`--similarity` exists and was not exercised.** The script takes it; nothing here has measured
   what it changes.

## No-claim

- One dataset of four. `email-dataset`, `nazario` and the out-of-distribution test have **not** been
  fetched or run here.
- These are **upstream's Jev answers**, replayed from the repo — this reproduces their comparison,
  it does not independently re-query Jev, and it therefore says nothing about Jev's current model.
- The four-decimal agreement with a two-decimal README is agreement at the README's precision, not
  bit-level reproduction; no seed or version pin was checked.
- `s1-rs`'s `triage` and `moderation` examples remain **unrun**: local Rust builds are denied by
  construction here and RCH refused with `critical_pressure=4`, no admissible workers. That is an
  infrastructure block, not a finding.
