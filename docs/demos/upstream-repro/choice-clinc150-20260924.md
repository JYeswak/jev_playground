# Can Choice say "none of the above"? CLINC150 out-of-scope routing, Jev vs Haiku (bead `jev-qw8`)

JevVariance (background agent of pane 1), 2026-09-24. Live lane, Jev pinned `jev-1.13.0`.
Pattern: intent routing with a none option (`docs-mirror/typesafe/primitives/choice.md:355`: "Add an
`other` or `none of the above` option when the list might not cover every input"), the Choice
primitive.

## Preregistered (committed before the first call)

**Question.** Banking77 (`jev-k3k`, [receipt](choice-banking77-20260924.md)) had no out-of-scope
rows, so it never asked the part of routing that decides whether a router can ship: saying no. On a
public set built for exactly that, does one Jev Choice with a "none of the above" option route
in-scope requests and refuse out-of-scope ones as well as Claude Haiku 4.5 answering the identical
Choice through TypeSafe's own adapter, and does its confidence make a usable abstention gate?

**Corpus.** CLINC150 (Larson et al., EMNLP 2019, CC-BY-3.0), `clinc/oos-eval` at
`828f8093932c8fe6ca7936c3d2e52903b1c523de`: `data/data_full.json` (sha256
`36923c3705a59e08fe9c3883d8bc2dd966ef93e22cb78ac41171782a698d56e0`; test 4,500 in-scope rows, 30
per intent, and `oos_test` 1,000 out-of-scope rows) and `data/domains.json` (sha256
`b947b579d3b8e74b06f93b01083d8efaff2888b43a3e362533bd88a6e1211b3a`; 10 domains of 15 intents). The
labels, including out-of-scope, are the dataset's, not ours.

**Subset rule** (`work/choice-clinc150/sample.py`, `rng = random.Random(20260924)`):
1. one domain, `rng.choice(sorted(domain names))`, and its 15 intents are the in-scope set;
2. every test row of those intents, in file order (15 x 30 = 450);
3. out-of-scope rows `oos_test[j]` for `j in sorted(rng.sample(range(1000), 300))` (300).

The draw is `auto_and_commute`: `current_location`, `directions`, `distance`, `gas`, `gas_type`,
`jump_start`, `last_maintenance`, `mpg`, `oil_change_how`, `oil_change_when`,
`schedule_maintenance`, `tire_change`, `tire_pressure`, `traffic`, `uber`. 750 rows, 40.0%
out-of-scope, in `work/choice-clinc150/subset.jsonl` (sha256
`03700e02174bb5ce2854f8ea0c28d2d7f486c215a0ddc39ae8f28a825d31154e`). Rebuild and diff:
`python3 work/choice-clinc150/sample.py --check` (fetches both pinned files, checks sha256).

**Constant first.** Always "none of the above": 300/750 (40.0%) overall, 0/450 in-scope, OOS recall
300/300. The same constant is the always-abstain control for the gate: it handles 300/750.

**The question, identical in both arms** (`work/choice-clinc150/run.py`). State
`{"user_request": <text>}`. One Choice named `intent`, instructions *"The intent of this request to
a car and commute assistant"*, 16 options: the 15 intent names humanized (underscores to spaces),
sorted, each undescribed (`None`), then `none of the above` described as *"A request that fits none
of the above"* (adapted from the vendor's example, `primitives/choice.md:388`). The none option is last on
purpose: the adapter resolves a tie to the first option (below), so a tie never lands on "none".

**Arms.**
- **Jev:** `typesafe-sdk-python` `TypeSafeClient`, `model="jev-1.13.0"`, 8 concurrent.
- **Incumbent:** `upstream/typesafe-ai/system-one-adapter-python` (`adffc2e`),
  `anthropic/claude-haiku-4-5`, `llm_answer_mode="probabilities"`, `normalize_probabilities=True`,
  structured outputs, default `RetryPolicy`, 8 concurrent. The runner also keeps the adapter's
  `debug`: `probabilityError` and `rawSum` for the question.

**The adapter's known zero-mass behaviour, handled before any call.** `jev-mly`
([receipt](adapter-uniform-20260924.md)) confirmed live that when Haiku returns an all-zero map,
the adapter reports a uniform distribution, confidence 0, and option #1 as a successful answer, and
that Haiku does this on inputs that fit none of the options. Out-of-scope rows are those inputs.
So every Haiku result is scored twice:
- **as shipped:** the adapter's answer as returned;
- **zero-mass = none:** each row with `rawSum == 0` read as Haiku answering "none of the above",
  which is what a caller who checks `debug` would do. This reading can only help Haiku on
  out-of-scope rows.

Each Jev-vs-Haiku verdict is taken as **the worse of the two for Jev**.

**Measures** (a row with no answer after one resume pass is wrong everywhere and counted in a
Failed column):
- overall correct over 750 (truth `oos` is correct only as "none of the above"), Wilson 95%;
- in-scope accuracy over 450; OOS recall over 300; OOS precision over the rows answered "none";
- **abstention gate**: route a row only when the chosen option is an intent and the arm's peak
  probability is >= t, otherwise abstain. Primary `t = 0.60`, the vendor's
  `MIN_CHOICE_PROBABILITY` (`cookbooks/consistency_choice_cookbook.md:87`, used at `:265`), one
  formula for both arms. Also reported at peak 0.80 and 0.90, and on each arm's returned
  `confidence` at 0.5 / 0.7 / 0.9 (descriptive; the two arms' `confidence` fields are not the same
  formula). Per row: routed right, misrouted (an in-scope row sent to the wrong intent, or an
  out-of-scope row sent to any intent), or abstained. A row is **handled** when an in-scope row is
  routed right or an out-of-scope row is not routed. Misroute rate = misrouted / 750; in-scope
  coverage = routed right / 450.
- **Shippable** (descriptive, per arm per threshold, fixed now): misroute rate <= 2.0% (15 rows)
  **and** in-scope coverage >= 80% (360 rows).
- Latency p50/p95 and tokens per arm.

**Paired test.** McNemar exact (two-sided binomial on discordant pairs) on per-row correctness.

**Pass rule, fixed now** (jev-k3k's rule, applied to two primary measures: overall correct, and
handled at peak >= 0.60; the constant for both is 300):
- **Feasibility:** an arm below 50% in-scope accuracy means the harness is measured, not the model;
  no verdict.
- **LOSE** if Jev does not beat the constant (300), or Jev is more than 3.0 percentage points below
  Haiku (more than 22.5 of 750 rows).
- **WIN** if Jev has more Jev-only-correct rows than Haiku-only-correct rows and McNemar p < 0.05.
- **NON-INFERIOR** otherwise.
- Each primary verdict is the worse one for Jev over the two Haiku readings. Jev **PASSES** if both
  primary verdicts are WIN or NON-INFERIOR. A LOSE on either goes to `NEGATIVE_EVIDENCE.md` with a
  retry condition.
- In-scope accuracy and OOS recall get paired McNemar tests too, reported as descriptive.

**Scorer.** `python3 work/choice-clinc150/score.py` (stdlib, no key, no network). Keyless
self-check before any call: on planted rows outside the tree (a perfect Jev arm and a Haiku arm
with 100 out-of-scope rows zeroed), it reports as-shipped OOS recall 200/300, zero-mass = none
300/300, abstains the zeroed rows at the gate, and takes the worse reading (WIN / NON-INFERIOR ->
NON-INFERIOR).

**Spend, planned.** 750 Jev calls and 750 Haiku calls, plus any resume calls.

## Result

NOT_RUN. Filled in after both arms.
