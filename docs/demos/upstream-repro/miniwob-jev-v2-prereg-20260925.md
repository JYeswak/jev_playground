# MiniWoB Jev v2 — held-out none-policy experiment

Bead: `jev-jy7t.1.7`
Status: preregistered before any Jev call.
Model: `jev-1.13.0`; official Python SDK from `upstream/typesafe-ai/typesafe-sdk-python` / the
existing `/tmp/jev-miniwob-jev/venv`. No comparator model and no Laya.

## Held-out split

Use every task in `work/game-floors/miniwob/tasks.json` (125 tasks) with exactly five fixed seeds:

```text
100,101,102,103,104
```

This is 625 episodes per arm. It is disjoint from the benchmark seeds generated by the floor
(`0..33` under its fixed `np.random.RandomState(42)`/`2 ^ 32` expression) and from all dev seeds
`>=9000`. The same `(task, seed, rep)` episode list is used for random, scripted, v1 and v2.

The floor remains unchanged: MiniWoB 1.1.0, Selenium, 0.5 s wait, 10-step cap, fresh page per
episode, raw reward > 0 and no harness error is success. Rows are appended to distinct files:
`work/miniwob-jev/rows/miniwob-floors-v2.s*.jsonl`,
`miniwob-jev-v1.s*.jsonl`, and `miniwob-jev-v2.s*.jsonl`.

## Arms

- **random:** existing `work/game-floors/miniwob/run.py` policy, unchanged.
- **scripted:** existing floor heuristic, unchanged.
- **v1:** `jev_arm.py live --seeds 100,101,102,103,104 --none-policy always`; all existing
  questions, span extraction, candidate cap, validator, retries, and state remain unchanged.
- **v2:** same command with `--none-policy after-page-change`. The only policy change is candidate
  availability: the first state offers `none`; after an action, `none` is offered only when the
  current page fingerprint differs from the previous observation. It is omitted when the page is
  unchanged. No new Jev question is added.

## Fixed bar

**PASS only if v2 beats v1 on the held-out episodes with exact paired McNemar p < 0.05 and v2-only
successes greater than v1-only successes.** Success is the existing raw-reward > 0, error-free
metric. Report Wilson intervals, b/c counts, p-value, random/scripted floors, v1 held-out versus
v1 benchmark split, calls, resolved model per call, input/output tokens and spend.

**KILL** if v2 does not satisfy both McNemar conditions. The purpose is to test whether the measured
v1 `none` failure mode generalizes, not to re-score the benchmark split that motivated v2.

No threshold, question text, seed, action candidate other than the fixed `none` rule, retry policy,
or bar changes after the first live call. A failure is retained as a measured result, not a ruling
about Jev generally.
