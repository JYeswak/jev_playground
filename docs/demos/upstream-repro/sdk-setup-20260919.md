# Installing the TypeSafe SDKs reproducibly (and why `uv run --with <path>` is not enough)

**Date:** 2026-09-19 · **Level:** `[live]` · Both probes below were executed.

## JavaScript — straightforward

```bash
npm i @typesafe-ai/sdk
```

```js
import { TypeSafeClient, noul } from '@typesafe-ai/sdk';
const client = new TypeSafeClient({ apiKey: process.env.TYPESAFE_API_KEY });
const r = await client.systemOne({ state: { text }, questions: { incident: noul('Is this a safety incident?') } });
r.answers.incident.probability;
```

**Trap:** there is no `client.systemOne.evaluate`. `systemOne` is a method on the client.

## Python — not on PyPI, so pin a git rev, not a local path

`pip install typesafe-sdk` fails: **not published.** The tempting fix —
`uv run --with /path/to/clone` — works on this machine and **is not reproducible anywhere else**.
It pins nothing and re-resolves each run, so a receipt built on it cannot be followed by a
stranger. That was a real defect in the first version of this lane's setup.

The durable form is a uv project whose dependency is a **git URL at a pinned commit**
(`work/pysdk/`):

```toml
requires-python = ">=3.12"
dependencies = ["typesafe-sdk"]

[tool.uv.sources]
typesafe-sdk = { git = "https://github.com/typesafe-ai/typesafe-sdk-python.git", rev = "420ef4ff…" }
```

plus `.python-version` = `3.12` and a committed `uv.lock`. Verified: **0 local-path references in
the lock**, resolves from git, `python 3.12.12 | typesafe_sdk 0.6.0`.

**When it publishes**, delete the `[tool.uv.sources]` block and pin a version in `dependencies`.
That is the one-line migration the git pin buys.

**Traps, both measured:**
- System Python here is **3.9.6**, where `msgspec>=0.21.1` has no resolvable wheel. Pin 3.12 in
  `.python-version`, never in the invocation.
- The Python SDK **requires** `instructions` or `criteria` on a Noul —
  `Noul(instructions="…")`. A bare dict returns **400 "Noul question must have criteria or
  instructions"**. The JS `noul()` helper does not require this. Cross-SDK asymmetry.
- `NoulAnswer` exposes **`.noul`**, not `.probability` (that is the JS field name).
