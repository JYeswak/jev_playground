## Boundary

No live calls, no key. W7.0 measured the client read-only; the fix wave then
edited `src/index.ts` (`guardedFetch`) and added `test/timeout-leak.test.mjs`
(T2 RED plant lived in `/tmp/w7t2`). Crash scripts at `/tmp/w7t9/` (+host,
+twohang). The SDK's own suite leaks the same AbortError (sdk-js receipt
T2), so the defect originates vendored-upstream of our wrapper.

## Fix (fix wave, same date): T9 now PASS on both hosts

Root cause: the SDK's timeout abort rejects the half-received response's
abandoned stream branch where no catch can observe it (a fetch-level catch
was proven insufficient by the regression test). Fix in OUR code only
(`work/jev-client/src/index.ts`, `guardedFetch`): we own the timeout —
our deadline fires at `timeoutMs - 25`, we abort our controller, we throw
the SDK's own `APITimeoutError`, so the SDK timer is cleared before it can
fire; `reason: "transport"` contract unchanged, vendored SDK untouched.
Regression test `work/jev-client/test/timeout-leak.test.mjs` failed
pre-fix (`unhandledRejection`), green post-fix. Proof: Node 30/30
timeouts clean exit 0; Bun 30/30 clean exit 0; suites 38/0.
`TESTS.md` registry updated.
