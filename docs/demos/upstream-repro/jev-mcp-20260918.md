judgment, and it works today.

Without a key the four e2e tests **skip rather than fail**, which is the right default and is why the
suite looked green at 9/9 before the key was supplied. A skipped test reporting as a pass is the
laundering this repo has now caught twice in its own gates; upstream avoids it by printing
`skipped 4`.

## Why this matters more than the benchmarks

The other repos measure Jev. This one **exposes it as three tools an agent can call**:

- `jev_verify` — does a claim contradict its evidence
- `jev_screen` — is this page or input hostile
- `jev_find` — which candidate matches, and is the answer absent

Every one of those is a question this lane asks by hand, in prose, dozens of times a day. `jev_verify`
is precisely the check the conductor performs when a pane reports a number and the control has to be
opened. The lane's own modal failure — citing a number without opening its control, roughly a dozen
recurrences in one session — is a `jev_verify` call with the claim and the receipt as evidence.

## The honest limit before anyone wires it in

`jev_verify` returning a probability that a claim is contradicted is **not** the same as opening the
control. It reads the evidence you hand it; it cannot know that the receipt you cited is the wrong
receipt, which was the actual shape of this lane's worst error (a figure that opened in a *ruling*
file rather than the *census* it claimed). So it belongs where a human is already reading the
evidence and wants a second opinion cheaply, not where the evidence itself is in question.

Measured cost elsewhere in this tree for comparable calls: 743–773 ms at 523–629 input tokens, and
`jev-benchmark` reports p50 378.5 ms at ~$0.0000173/call.

## No-claim

- Four e2e tests are a **smoke test of the transport and the three tool shapes**, not a measurement
  of judgment quality. Nothing here scores Jev's answers against labels.
- The key was supplied through `infisical run` and never written to disk, a log, or this file. No
  spend figure is recorded because the suite does not report one; four calls at the rates above is
  immaterial but unmeasured here.
- `dist/` and `node_modules/` were already present in the clone, so this did **not** prove a build
  from source. `npm run build` was not run.
- Nothing is wired into this harness yet. The paragraph above is an argument for doing it, not a
  record of having done it.
