**Status: planning draft, NOT execution-ready.** This is the single editable plan of record for the present reality check and bridge. Before converting it 1:1 to beads, complete four substantive independent review rounds, resolve structural objections, and prove its graph and acceptance contracts. ## 0. Mission and decision

Validate Jev live with the pinned `jev-1.13.0` model on externally authored inputs against a pre-call committed bar and a same-input incumbent, state cost, build only what survives, make an omp surface fire, dogfood it on organic work, and publish a stranger-runnable README. A fixture, SDK test, installed extension, or single positive tool call is not consumer benefit. A reusable *decision workflow* usable in another project is a candidate product, not an established need or a license to build a generic platform before local value is measured.

**User intent (stated):** make Jev easy to apply to any project, improve our own work, and find useful and fun examples. **Design hypothesis (ours, revisable):** teach one small, auditable pattern—state → typed question → validated answer → explicit policy/abstention → observed outcome—through the existing kit, then prove it on an unrelated project before generalizing. Portability means someone outside this repo can run a complete workflow and understand what Jev *did not* establish. It does not mean every app has an omp hook, identical risk tolerance, or a universal confidence threshold.

The first local candidate remains **advisory tool-call risk triage**, because an existing held-out fleet sample supplies paired labels and a concrete incumbent. But a candidate with plentiful labels and no operator benefit is not the winner. P0/P2 test demand and prevalence before locking it in. Rerank/search is a separate candidate: its organic open attribution must pass feasibility, and reading a result is not by itself a quality label. Web-result *enforcement* is excluded on its recorded design: fresh held-out web-screen attack catch was 15/40 against a preregistered >=35/40 bar, despite planted L3 firing (`EVAL.md:2604-2612`). A new question design gets a new pre-registered test, never a rewritten historical verdict.

### Executive summary and goals / success metrics

This is a **feature-grade plan for a portable decision recipe with local proof**, not a constitution for an all-purpose AI framework. The smallest useful deliverable is one named local operator who gets better decisions than the current gate/search incumbent without excessive false interruptions, plus one external adopter who can reproduce the same *evaluation method* (not the same threshold) on a different domain. A second unrelated transfer checks that “portable” is not an accident of one app. Until the user's halt lifts, this plan has no authority to run those trials.

### Background context for a new implementer

Jev is TypeSafe's metered typed-decision API: a JSON `state` and named Choice/Score/Noul questions produce structured values, not generated prose. This repo is a shared `main` evaluation lane with vendored upstream SDK and adapter sources, a local TypeSafe documentation mirror, real experiments under `work/`, an `EVAL.md` receipt ledger, and a `kit/` CLI plus project-scoped omp templates. `AGENTS.md` owns the restrictions: never write secrets or customer response bodies into this tree; never commit into or push vendored clones; stage only owned paths and do not silently alter other agents' work. Pinned upstream sources are the contract; `docs-mirror/typesafe/concepts/use-case-map.md` supplies candidate categories but not success evidence. The operator's existing deterministic gate is a real incumbent; TypeSafe's official SDK is the portability incumbent. This plan compares against both, rather than imagining Jev starts from a blank application.

Existing L3 receipts for `jev_rerank` and webscreen are seam-specific. Gate-shadow and web-search hook reachability, organic benefit, and external-project portability have different evidence and cannot be inferred from them. Current README contains both exercised numbers and unearned interpretations: §1 below is a bounded audit and P0 must finish a fresh inventory. The plan assumes no one is operating a background Jev experiment on behalf of this session. Every transition from a public benchmark to an organic workflow must carry a new bar and its own outcome labels.

### Non-goals and authority boundary

- No universal application framework, dynamic prompt registry, runtime policy language, copied SDK client, new billing system, or `:free` comparator that is actually paid. The official Python/JS SDKs are the incumbent for transport and response types; the existing `jev ask` is already a generic entry.
- No automated destructive command, medical decision, payment, account lock, or moderation ban. Advisory decisions are only eligible for actions their host explicitly permits; a Jev result never creates authority.
- No assertion that published TypeSafe use cases, model calibration, or a peer-reviewed *different model's* success transfers to Jev. Scores from our local fixtures are policy tests, not live API results.
- No fixed success threshold copied between domains. P4/P11/P12 freeze their own bar using observed prevalence, base rate, false-action cost, feasibility and independent labels; after that commit the bar is immutable for that run.
- No fresh clone, external repo install, or data shipment during the planning-only halt. A plan may specify these future checks without performing them now.

### User workflows and architecture

1. **Local operator:** a real omp tool call occurs; the existing gate makes its ordinary deterministic decision. An observer hashes a safe event ID and records eligibility before any Jev request. The injected transport asks the pinned model only the narrow semantic question. A validator checks the full response; local policy abstains or logs advice. The operator sees nothing on the healthy path. An independent later label joins the original event ID; paired incumbent/experimental metrics and money are computed from eligible units, never from only answered ones.
2. **External adopter:** starts with a domain-specific example from the official use-case map, checks that the decision has a human purpose and available external labels, and runs `jev ask choice|score|noul --state FILE --question FILE --robot` or the official SDK. Offline policy/refusal can run without a key; real Jev returns a pinned answer only with an external key. The adopter writes their own action/abstain code and compares it to their incumbent. If direct SDK is simpler than our kit, the portable artifact is a proven recipe and README, not an extra package.
3. **Reviewer/stranger:** follows README on a fresh checkout, sees exact commands, pinned data, costs, failures, and `Boundary` lines; a completed tool installation alone never becomes a consumer claim. The non-author reviewer rescales raw row files and flags any duplicate ID, missing outcome, weakened gate, or unmatched comparator before a bead can close.

```text
source event ─> eligibility + privacy/feasibility gate ─> transport (SDK or existing CLI)
     │                   │                                    │
     └── same-row incumbent ──────────────┐                   ▼
                                          │       response schema + numeric validator
                                          │                   │
                                          └── paired ledger <──┴── local policy/abstain
                                                   │                 │
                                        independent label       permitted operator action
                                                   └──────── outcome join ────────┘
```

Transport, question design, validation, policy, authority, outcome and publication are separate owners. The *application* owns action and privacy; the kit may supply a typed answer but cannot infer local permission. The official docs at `docs-mirror/typesafe/concepts/use-case-map.md:11-32,178-191` motivate potential categories/shapes, while `kit/bin/jev.mjs:59-85` and `kit/src/install.ts:5-34,48-66` are the actual present portability surfaces.

## 2. Authority and invariant contracts

1. **Source of evidence.** Public data snapshot and its labels must be pinned independently of our score code; record corpus hash, item IDs, prevalence, split, exclusions, question bytes, model ID, incumbent ID and answer schema. Check feasibility before paying: offered correct option, input within the documented bound, attainable statistical bar. No labelled test pattern typed from imagination.
2. **Bar before spend.** Freeze the primary statistic, unit of analysis, effect direction, sample size/power or reachability, invalid-row policy, confidence interval/test, false-alarm ceiling, call cap, and every stop condition in a commit before the first call. A bar that is unreachable produces NO-RUN, not a new bar. No retrospective change to a failed bar.
3. **Incumbent.** Execute the current deterministic gate on the same frozen commands, with the same labels and timestamp provenance. For any model-vs-model superiority claim, pair the permitted `:free` LLM on identical states/questions; if its quota prevents a valid paired N, mark the model comparison NOT_RUN, never infer a win from a Jev-only arm. No paid comparator API.
4. **Authority.** Observe first. Advise only after the preregistered bar and independent recount. Enforcement requires a *separate* explicit decision backed by organic data and a reversible intervention policy; no Jev probability authorizes deletion, publication, or privileged action. A malformed answer, absent key, timeout, 401/402/403, or rate cap produces a typed refusal/NOT_RUN and leaves the incumbent path unchanged. Never count `calledModel` true for an unattempted request or false after one was sent.
5. **Outcome ledger.** Record `suggested`, `permitted`, `executed`, and `outcome` as distinct fields. Store hashes/session identity and redacted action metadata, not command bodies or customer state. Join by an observed event ID; a missing join is missing evidence, never negative outcome. Count row inclusion and exclusion and spend per scored and per failed call.
6. **Promotion.** A passing offline policy test or L2 load check is not live proof. A real omp positive and planted refusal establish L3 for that seam; a healthy organic session with counted decisions, latency/cost and silent valid path may reach L4. Promote a *consumer claim* only if both the frozen paired bar and operational shadow bar pass; demotion is unconditional when contradictory evidence appears.

### 2a. Current research → discriminating test, not borrowed performance

**What the sources establish.** TypeSafe's local 2026 mirror describes five application categories (automation, real-time, map/reduce, verification, harness) and ten decision shapes at `docs-mirror/typesafe/concepts/use-case-map.md:11-32,178-191`; `docs-mirror/typesafe/patterns.md:9-20` describes fan-out, confidence routing, composite scoring, and intent routing. Those are *vendor-proposed design spaces*, not externally measured gains. The public [TypeSafe workflow evaluation](https://evals.typesafe.ai/) tests vendor-chosen workflow/reference configurations; it does not validate this lane's organic labels or business policy. [Chuang et al., ICML 2025](https://proceedings.mlr.press/v267/chuang25b.html) report gains from *trained confidence tokens* in routing/rejection relative to verbalized/logit baselines. That model/training method is not Jev: transfer only the question “does abstaining or escalating at this cut improve selective risk at measured coverage?” [Radharapu et al., ACL Industry 2026](https://aclanthology.org/2026.acl-industry.14/) use hidden-state linear probes with Brier loss for LLM-judge calibration, reporting cross-domain evaluation and a conservative-easy-set tradeoff. A closed Jev API does not expose their hidden-state probes: do **not** propose plugging them into Jev; transfer only Brier/risk–coverage diagnostics on Jev's observable responses, with held-out human or published labels. Paper gains are never Jev claims.

**Loss-depth budget is evidence-bounded, not effort theater.** For each failure: (1) keyless reconcile recorded row IDs, missing evidence, response shape, prevalence and baseline; (2) classify errors into missing input evidence, question design, harness bug, or model limitation and count each cluster; (3) propose up to five one-variable hypotheses with distinct predictions; (4) replay a fixed *development-only* sample including at least one known-bad and one known-good row; (5) commit a fresh held-out bar before any new live call, then call once per preregistered run. A failing bar remains failed. Stop a design when a required source cannot be supplied, a cheaper incumbent dominates under the fixed consumer loss, or one controlled redesign plus held-out retest reproduces the same model-limited failure. A new independent fact/model/version can reopen it with a documented retry condition. “Not yet measurable” is HOLD, not a kill or promotion.

**RB-01 — Bounded rigor binding (eval harness, not a new model).** Invariant: every included binary-label probability and its independent label contributes to the *same* calibration, discrimination, coverage and spend denominator; missing/invalid rows never vanish silently. Mechanism: for eligible Noul probabilities, calculate Brier and log loss (and fixed-bin ECE with bucket counts), then risk–coverage and precision at the frozen policy cut on the same resolved rows. Avoid conflating Choice `confidence` with calibrated correctness probability. Compare incumbent on exactly these IDs and keep latency separate. Falsifiers: swap positive/negative labels, set every probability to a constant, or remove one cohort from one metric; the paired-result/calibration checker must fail, report no-signal, or report a changed denominator rather than retain its headline. Independent reviewer checks source row and label hashes. Source: `rigor-atlas` prescription `proper-scoring-calibration-gate`; measured exemplar `franken_overlap/crates/fo-core/src/metrics.rs:152-174` computes Brier, clipped log loss and calibration on one sample. Authors' math is reusable; their performance numbers do not transfer. Claimed result class after execution is *statistical on the named held-out cohort*, never a distribution-free guarantee, Jev API calibration claim, or permission to act. Owner: P2/P4 for the contract, P5 for the receipt, independent P5 reviewer for closure.

### 2b. Local benefit, portability, and fun examples

**Local first, with a before/after.** Gate triage improves our work only if correct harmful-call review is increased *at the same false-interruption cost* and total time is acceptable; log operator action, not just flags. Reranking improves our work only if paired downstream evidence access/answer quality improves for our own real searches; a standalone public ranking win is a research result. Claim checking improves our work only if independent support errors decrease without unacceptable review burden. If none of these improves a real user workflow, be explicit that the kit is an educational demo, not an operational integration.

**Minimum portable decision recipe, not a premature framework.** The external adopter supplies a JSON `state`, one typed question (Choice/Score/Noul), independent labels and a current baseline, a local policy including abstention, and an outcome join key. Reuse `jev ask` / first-party SDK; pin the model; validate response schema and every numeric invariant; place credentials outside source; bound calls and check feasibility; return `ANSWER`, `REFUSED`, `NOT_RUN`, or `ERROR` with counts and spend; preserve the original input. No domain-independent threshold is shipped. The new project owns its domain policy, privacy boundary, action authority and human-review flow. omp installation is optional for omp users only. A non-omp project should not receive `.omp` templates to be called supported.

**Proof of transportability:** run the recipe in this lane *and one independently owned, unrelated project* against public, non-customer rows, with one-command keyless policy proof, explicit no-key NOT_RUN, pinned live Jev answer after a committed bar, same-row incumbent, a planted malformed/refusal case, and a human-observed result. Repeat on a second unrelated domain before claiming “works for any project.” The first two transfers measure adaptation time, new code/files, schema mismatches and policy differences. Failure to transfer is evidence about the interface, not automatically about Jev. Never claim identical model performance across domains merely because the same API call works.

**Engaging, bounded examples (ideas, not measured capabilities):**

1. **Research-paper claim checker:** SciFact claims and cited abstracts (already public, first verify split and source in existing receipts); Choice `supported/refuted/insufficient`. Incumbent: provided corpus baseline or exact lexical match. Human use: author verifies a sentence before publication. Not proof of scientific truth beyond evidence.
2. **A personal reading-list sorter:** publicly licensed article abstracts with existing human topic/relevance labels, Score `relevance to this query`; compare BM25 and human pick. Use a tiny browser/UI demo only *after* offline ranking and a real opened-use case. “Interesting” is subjective, so preregister whose preference counts.
3. **Game-dialogue route selector:** publicly released game episodes with recorded legal actions and gold rewards (for example the pinned MiniWoB/Jericho work only if their real observation/action contract is reproduced); Choice among offered actions. Compare a deterministic/default planner on equal state and budget. Wrong moves are not made safe by confidence; no claim from invented episodes.
4. **Customer-support inbox practice:** a public labeled ticket dataset with permission and no customer secrets, Choice department and Noul urgent escalation. Compare existing rule/queue and free model, measure missed urgent cases *and* operator interruptions. Vendor `use-case-map.md:97-104` motivates the shape but supplies no result on our data.
5. **Community moderation simulator:** externally labeled public posts and published moderation rules, Noul policy violation with a visible abstain/review band. A fun sandbox allows threshold exploration on dev rows; the held-out bar is fixed before live calls. No automatic real-user moderation until false-positive and appeal outcomes are observed.

For each example name the corpus URL/revision, license, actual labels, date, model, question shape, incumbent, eligibility, and safe/no-key lane before it becomes a demo. If no such corpus is available, keep it an idea, not a fake demonstration.
