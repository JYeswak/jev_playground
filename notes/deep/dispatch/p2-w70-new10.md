## 3. Tools and rules

- One subagent per clone (`task` tool). You re-run each subagent's decisive command before it
  enters a receipt; a subagent's "done" is not evidence.
- **Rust only via RCH on Contabo** (`skill://zeststream-rch`): `RCH_VISIBILITY=verbose rch exec --
  cargo test -j 2 ...`, never local cargo, never `--target`. A result counts only with
  `Selected worker`, `Remote command finished: exit=N` and the tool's own `test result:` lines.
  Workers were repaired at 03:36Z; if a negative test passes, confirm on a second worker and check
  `stat -c %F /dev/null` on the odd one (NEGATIVE_EVIDENCE.md R78).
- Toolchain: `uv` for Python, `npm` for JS per AGENTS.md. Where a clone ships only a pnpm or bun
  lockfile, run its own package manager against its own lockfile (the lockfile is part of what we
  evaluate) and record the deviation in the receipt.
- **Clones stay untouched:** `git -C <clone> status --porcelain` before and after; plants go in a
  `/tmp` copy. Installing a clone's own dependencies into it is allowed; adding or upgrading one is not.
- **One main:** never create a branch or worktree in jev (the pre-commit hook refuses the commit
  anyway). Commit on `main`, explicit paths, `git diff -- <shared file>` shows only your hunks,
  never amend. The Muse panes are paused and Agent Mail may still be recovering: coordinate by `ntm`.
- Depth rule (`notes/deep/dispatch/DEPTH-DIRECTIVE.md`): a NOT-RUN carries the exact command,
  verbatim output, a `file:line` cause, and two routes tried.
