THE ISSUE IS GENUINELY FIXED. skillranker #3 CLOSED 2026-09-20T21:13Z. Dicklesworthstone shipped
native macOS support through 6b5d17c4 and credited our report and our expanded diagnosis. We pulled
abf909d -> a6f1ff0 (200 commits, not the 74 I first reported — I measured against a stale

WE CANNOT CHECK IT. Three independent walls:
  1. LOCAL RUST IS DENIED BY CONSTRUCTION. The toolchain cargo at
     ~/.rustup/toolchains/nightly-aarch64-apple-darwin/bin/cargo is itself a MANAGED SHELL SCRIPT
     whose own comment calls it "the one layer they cannot dodge". Its documented bypass
     (RCH_CARGO_WRAPPER_BYPASS=1) is caught by a second guard: "LOCAL RUST BUILD DENIED BY
     CONSTRUCTION — CONTABO OR BUST. The real compiler is not reachable from any local path."
  2. NO DARWIN WORKER. cargo check --target aarch64-apple-darwin refuses with
     os_gate_excluded=4 required_os=darwin — no worker declares os = "darwin" in workers.toml.
     All four Contabo boxes are Linux.
  3. MACH-O CROSS-COMPILE FAILS AT THE FIRST C DEPENDENCY. I followed the refusal's own documented
     path (RCH_REQUIRE_REMOTE=1 rch exec -- cargo check --config build.target=..., never --target).
     It ran 347 seconds on contabo-3 and died exit 101 in ring-0.17.14:
        cc: error: unrecognized command-line option '-arch'
        cc: error: unrecognized command-line option '-mmacosx-version-min=11.0'
     Rust cross-compiles. The C dependency does not: Linux cc rejects Apple flags. That needs an
     osxcross toolchain or macOS SDK on the worker, and neither is provisioned.
