# Round 2 ideas — daily machine time and spend

**Scope:** ideas for this Mac's ordinary omp sessions, NTM fleet, hooks, Beads, and CI. This is a proposal, not a measurement or implementation. Model-call estimates below are ceilings derived from stated caps/assumptions, not observed costs. Jev price assumption where used: $0.042/M input tokens; output free. Keep existing safety behavior unchanged unless an explicit held-out bar passes.

## Ground truth and exclusions

- The command gate cascade is already a measured win: about 96% locally screened, and a 7-day blind audit found 0/950 harmful among nimble-cleared commands; recursive-delete pre-rule is part of the current cascade. Do not repeat that work as a new idea.
- Memory filtering already runs four-wide: 1,308 ms versus 3.3 s serial; 20/20 within budget and byte-exact pruning. Held-out drop precision is 0.978/0.985; the keep side is only about 0.22, with a median 797 tokens removed per turn. R137 tested three single-question rewordings and found no useful keep-side lift; retry only a structural decision change, not more wording variants.
- The web-result screens are already on a shared capture/score path; rerank is OFF after 0 opens in 15 answered cases. Semantic skill hints and lexical variants are exhausted/OFF; R135's semantic shortlist got only 4/20 versus the required 8/20. Needs-human enrichment is deleted after the 1/1 audit; no Cass rerank without traffic. No Nimble substitution for injection, webscreen, or memory relevance: it lost those tasks.
- Find-over-grep, hard-task auto-thinking (-16% cost at equal-or-better outcome), and memory concurrency are already wins. Do not spend another idea on their already-measured implementation.
- Relevant closed beads include `jev-syje` (nimble-cleared audit), `jev-11qz` (memory concurrency), `jev-m959`/`jev-9tkx` (memory keep-side results), `jev-n4eu` (shared screens), `jev-r8dp` (per-process cap census), and `jev-izfl` (CI recovery). Same-day closed-bead inventory also includes `jev-ib1h`, `jev-zbb1`, `jev-zljn`, and `jev-ygyp`, which close the rerank, semantic hint, page enrichment, and Cass paths respectively.

## Winnow: best five, best first

### 1. Shared daily admission budget for optional Jev work

**Decision:** deterministic budget admission; Jev remains the judge on its already-qualified surfaces. Do not use a model to decide whether to spend on another model call. **Seam:** machine-wide ledger/admission across profiles, processes, and hook surfaces, restricted to shadow/optional work. Required gate and injection enforcement must not be silently disabled. **Metric:** actual input tokens, call totals, exact provider cost, cap denials, and enforcement coverage per UTC day from session files and hook logs. **Bar:** publish a $0.25/day optional-work ceiling, demonstrate no cap overruns over seven days, retain all required positive-path coverage, and prove the ledger counts concurrent pane calls correctly. The current total is about $0.32/day, so this is a testable reduction target, not a promise of a 22% saving; if required calls alone exceed the ceiling, report that and do not shed them. **Cost/day:** no additional Jev; ceiling is the policy. **Planted negative:** concurrently submit calls from multiple profiles beyond the cap and verify optional calls are denied deterministically, while a required planted gate/injection positive still reaches its existing judge and is acted on. 

**Why first:** `jev-r8dp` directly measured cap saturation across processes/surfaces (including memory 1,140 observed against 600 configured; gate 853/3,000; injection 232/300; web 138/75). Per-process caps are not a machine-level spend bound. Current overall spend is only ~$0.32/day, so the point is not to build accounting theater: the admission seam must actually stop optional spend at the declared ceiling and reconcile actual costs. It is deterministic, can save money immediately when overlapping caps would otherwise exceed budget, and does not ask a weak local model to replace a stronger judged decision. Key risk: careless prioritization could starve a useful shadow or required check; separate mandatory enforcement from optional observation and make every denial visible.

### 2. Two-question memory keep gate, structural R137 retry

**Decision:** two separately validated Nouls joined by a conservative AND policy: memory must be useful for this request and current/usable; keep only when both pass the existing threshold. This is explicitly the changed decision structure R137 permits, not another wording tweak. **Seam:** memory-filter scoring before injection; keep byte-exact inputs and current concurrent execution. **Metric:** held-out keep precision, drop precision, retained irrelevant tokens/turn, known-good memory retention, p95 start latency, and total input tokens. **Bar:** freeze a held-out labelled set and bar first; require keep precision >=0.42 (20 percentage points above the ~0.22 baseline), drop precision >=0.90, no loss of known critical memories, and net reduction in injected irrelevant tokens; do not enforce if any leg misses. **Cost/day:** at most 2x current judgment volume, bounded to $0.02/day for the pilot (about 476k input tokens at $0.042/M). **Planted negative:** a memory that is useful but old/currently applicable must not be dropped solely because the second question is uncertain; prompt echo remains a must-drop case.

**Why second:** memory already has a real productivity lever: 0.978/0.985 drop precision, median 797 tokens removed, and four-wide latency reduced from 3.3 s to 1.308 s. But keep precision near 0.22 means most retained memories are still irrelevant; the existing question-rewording family is exhausted by R137. A structural conjunction is a new hypothesis with a direct user-visible denominator: irrelevant tokens actually injected per turn. It attacks the waste without throwing away the reliable drop side. It costs extra calls and could over-drop; strict labelled boundaries, a small daily cap, and the planted valuable-old-memory negative keep the experiment bounded.

### 3. Exact repeated find-query cache with mutation invalidation

**Decision:** Jev only on cache miss; no semantic query matching. **Seam:** session-scoped cache in the native find execution path, keyed by exact query plus repository/session identity, invalidated on any file-changing tool event and repo/index refresh. **Metric:** exact repeat rate in session files, native calls avoided, token spend saved, file-open success, and stale result IDs. **Bar:** at least 5% fewer find calls over a 7-day organic window; 0 stale results in a recorded write-then-repeat-query replay; no decrease in successful located-file opens. **Cost/day:** no new Jev calls; savings = avoided calls × measured per-call cost, reported rather than forecast. **Planted negative:** same exact query before and after a file create/delete/rename must return the post-mutation result, not the cached list.

**Why third:** find is the largest native surface in `expected.json`, with high daily traffic and established value: 576 tokens/file versus grep's 5,293, and controlled 404 versus 1,861 at equal success. A small exact-match repeat cache could remove redundant native calls without revisiting ranking quality or replacing find with grep. This ranks below the budget and memory work because no repeated-query rate is established in the supplied evidence; the first step is a session-file census, and the proposal dies if the exact-repeat fraction is too small. Cache invalidation is the make-or-break correctness property; never reuse across a mutation.

### 4. CI repeated-failure fingerprint cache (failure diagnostics only)

**Decision:** none; stable deterministic fingerprint, cache prior diagnostic context only, never a passing test result. **Seam:** CI artifact summarizer keyed by exact commit/tree and failing test identity. **Metric:** duplicate diagnosis/runner time avoided, stale-key hit rate, distinct failure count retained. **Bar:** at least 20% less duplicate diagnostic work on a held-out set of repeated failures; 0 distinct failures merged and 0 test executions skipped. **Cost/day:** $0 Jev; compute/storage cost measured as GitHub runner time. **Planted negative:** same test name with changed source/commit and a different assertion failure must create a separate fingerprint and retain its own log.

**Why fourth:** the closed CI bead `jev-izfl` found a deterministic regression/gate issue, and the duel report explicitly rejected Jev CI triage because the pain is deterministic. This idea follows that evidence rather than adding an LLM call: reuse only diagnosis context for the same failure identity, while every run still executes required tests. It could improve time-to-understanding when a broken main repeats, but there is no repeated-failure prevalence in the supplied numbers, so it needs a 30-day occurrence census before implementation. If the cache saves no measurable operator or runner time, retire it.

### 5. Exact duplicate context removal at assembly time

**Decision:** none; byte-identical deduplication only, preserving source precedence and all unique content. **Seam:** omp context assembly before the first model request. **Metric:** duplicated tokens by source in session files, total input tokens/session, and exact unique-source coverage. **Bar:** identify repeated identical blocks accounting for >=2% of input tokens, remove them, then demonstrate >=2% lower median input-token use over a held-out session set with every unique policy block preserved byte-for-byte. **Cost/day:** $0 Jev; expected savings measured in provider input-token usage, not estimated from file size. **Planted negative:** two near-duplicate but conflicting instructions both remain present and ordered; only identical byte blocks are deduped.

**Why fifth:** the prior 2,047-to-600-line AGENTS trim produced a clear context-cost lever, and live session files can measure whether repeated context remains. The upside is persistent, deterministic savings across daily sessions without another paid decision. It ranks fifth because this round's supplied measurements do not quantify current duplicate context volume; a source-attributed census is a prerequisite. Do not compress or summarize unique instructions, which can silently change policy semantics.

## Rejected from the final five

- More Nimble routing for injection, webscreen, or memory relevance: measured loss; Nimble stays confined to the gate cascade.
- Another gate cascade expansion: existing 96% free screening and 0/950 harmful audit are already wins; no unmeasured command class is nominated here.
- Web-search rerank or alternate ranking: R134 found 0 opened picks and 0/6 for both Jev and shuffled control; the agent-side open behavior must change first.
- Semantic/lexical skill-hint variations: R133/R135 close those designs; no retry without a method reaching >=8/20 keyless shortlist recall and then the original quality bar.
- Needs-human enrichment: R136's direction is deleted; reopen only after >=10 organic pages show <80% decision-present.
- Cass-hit reranking: closed `jev-ygyp` found no useful traffic in the sampled collection; do not spend on ranking without new traffic.
- Another single-Noul memory wording variant: R137 is a model-limit finding for that family; only the structural proposal above is retained.
- Jev CI failure triage: deterministic CI regressions are better served by stable test identities/fingerprints, not another judge.

**Decision:** pursue #1 only after validating that the optional/required distinction is represented correctly in the live logs; #2 is the best bounded experiment if a labelled memory set is available. #3–#5 first require the census named above. None is implemented or measured by this document.
