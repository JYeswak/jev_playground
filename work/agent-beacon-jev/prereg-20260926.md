## Frozen Jev arm

One System One request per row, model `jev-1.13.0`, containing the exact three Nouls from `RubricQuestions` (`evaluator.go:31-35`) and the exact true/false criteria constructed by `jevQuestions()` (`evaluator.go:300-316`):

1. `task_success`: “Did the trace complete the user's engineering task successfully?”
2. `reusable_correction`: “Does the trace contain a correction or debugging pattern that future agents should reuse?”
3. `evidence_supported`: “Is the reusable lesson supported by concrete events in the trace?”

The Jev score is the Beacon implementation's arithmetic mean of the three returned probabilities (`evaluationScore`, `evaluator.go:250-258`). A live row is valid only when all three numeric Nouls are returned and the model id is recorded.

## Baseline and bar

The prevalence floor is the majority constant: always predicting `OK` is 40/70 = 57.14%; a constant predictor has AUROC 0.5. The preregistered deterministic baseline is `close_reason_len` (higher length predicts OK), with AUROC computed pairwise with 0.5 credit for ties. Offline baseline AUROC is 0.6920833333.

Primary bar, computed only after the live rows are complete: Jev's AUROC for the mean-of-three score must be at least **0.70** and at least **0.10 above the length baseline** (target `0.7920833333`). No threshold, question subset, label mapping, or direction may be changed after seeing Jev output. A result below the bar is a measured failure of this rubric/state design, not a license to tune the bar.

Reachability: the theoretical perfect AUROC is 1.0, which exceeds the frozen target 0.7920833333. Separately, `scripts/bar-reachable.py --mode rate --trials 40 --threshold 0.70` must return `REACHABLE` before live calls as the positive-count structural guard.
